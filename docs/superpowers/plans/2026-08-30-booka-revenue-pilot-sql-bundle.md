# Booka Revenue Pilot SQL Bundle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce one reproducible, transactional SQL file that applies and verifies Booka revenue-pilot migrations 122 and 123 in the Supabase SQL Editor.

**Architecture:** A small Node.js generator reads the two authoritative migration files and their two verification scripts, removes only the migrations' top-level transaction wrappers, adds a prerequisite-table guard, and wraps the combined result in one transaction. A Node built-in test compares generated output byte-for-byte with the committed release artifact and verifies its safety markers.

**Tech Stack:** Node.js 20 built-in `fs`, `path`, and `node:test`; PostgreSQL/Supabase SQL.

**Spec:** `docs/superpowers/specs/2026-08-30-meta-pilot-readiness-design.md`

## Global Constraints

- The output path is exactly `db/releases/2026-08-30-booka-revenue-pilot.sql`.
- The bundle must apply migrations `122_booka_revenue_requests.sql` and `123_revenue_attribution_verification.sql` in one transaction.
- The bundle must execute both verification scripts before its single final `commit;`.
- The bundle must fail before schema mutation when `public.sias_outcome_attributions` is absent.
- The bundle must not include either disposable baseline script or create database roles/test data.
- Original migration and verification files remain authoritative and unchanged.

### Task 1: Deterministic SQL Editor release generator

**Files:**
- Create: `scripts/generate-booka-revenue-pilot-release.mjs`
- Create: `scripts/generate-booka-revenue-pilot-release.test.mjs`
- Create: `db/releases/2026-08-30-booka-revenue-pilot.sql`

**Interfaces:**
- Consumes: the UTF-8 contents of migrations 122/123 and their verification SQL files.
- Produces: `buildBookaRevenuePilotSql(): string` and `writeBookaRevenuePilotRelease(): string`, where the latter writes the release and returns its absolute path.

- [ ] **Step 1: Write the failing generator contract test**

Create `scripts/generate-booka-revenue-pilot-release.test.mjs` with tests that:

```js
import assert from 'node:assert/strict';
import { readFileSync } from 'node:fs';
import test from 'node:test';
import { buildBookaRevenuePilotSql, outputPath } from './generate-booka-revenue-pilot-release.mjs';

test('committed SQL bundle exactly matches generated output', () => {
  assert.equal(readFileSync(outputPath, 'utf8'), buildBookaRevenuePilotSql());
});

test('bundle is atomic, guarded, verified, and excludes disposable setup', () => {
  const sql = buildBookaRevenuePilotSql();
  assert.equal((sql.match(/^begin;$/gim) ?? []).length, 1);
  assert.equal((sql.match(/^commit;$/gim) ?? []).length, 1);
  assert.match(sql, /to_regclass\('public\.sias_outcome_attributions'\)/);
  assert.match(sql, /booka_revenue_requests missing columns/);
  assert.match(sql, /sias_outcome_attributions missing columns/);
  assert.doesNotMatch(sql, /create role anon/i);
  assert.ok(sql.lastIndexOf('sias_outcome_attributions missing columns') < sql.lastIndexOf('commit;'));
});
```

- [ ] **Step 3: Implement the generator**

Create `scripts/generate-booka-revenue-pilot-release.mjs` using only Node built-ins. It must:

1. Resolve paths relative to the repository root.
2. Read these sources in order:
   - `db/migrations/122_booka_revenue_requests.sql`
   - `db/migrations/123_revenue_attribution_verification.sql`
   - `scripts/sql/verify_booka_revenue_requests.sql`
   - `scripts/sql/verify_revenue_attribution_verification.sql`
3. Remove only a migration's first standalone `begin;` and last standalone `commit;`, throwing when either wrapper is absent.
4. Prefix the output with:

```sql
-- Booka Revenue Pilot — staging SQL Editor release
-- Generated by scripts/generate-booka-revenue-pilot-release.mjs.
-- Run only against the intended staging Supabase project.

begin;

do $$
begin
  if to_regclass('public.sias_outcome_attributions') is null then
    raise exception 'Prerequisite public.sias_outcome_attributions is missing; apply its foundation migration before this release';
  end if;
end $$;
```

5. Add `-- BEGIN <path>` and `-- END <path>` markers around every source.
6. End with one standalone `commit;` and a trailing newline.
7. Export `outputPath`, `buildBookaRevenuePilotSql`, and `writeBookaRevenuePilotRelease`.
8. Write the file only when the module is invoked directly.
